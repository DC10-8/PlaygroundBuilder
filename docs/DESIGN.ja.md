# Playground Builder 設計メモ

利用者向けの説明はリポジトリ直下の [README](../README.md) を参照。ここは内部の仕組みと検証の記録。

範囲を指定すると公園を丸ごと作り、近所の住民が実際に来て使うMOD。

既定の「公園レイアウト」では、次のものを自動で作る。
- 中央の広場とシェルター
- 入口から広場への園路（歩行者道ネットワーク）
- 役割別のゾーン（アクティブ / 幼児用 / 水遊び・砂場 / 芝生）
- トイレと案内板、ピクニックテーブル、水飲み場
- 外周の植樹と柵

## ビルド
1. `dotnet build -c Release -p:CitiesPath="<CS1のインストール先>"` を実行する（環境変数 `CITIES_SKYLINES_PATH` でも可）。Mods フォルダへ自動でコピーされる
3. Harmony が必要（Workshop: *Harmony 2.x*）

## 言語
オプション画面の「言語 / Language」で、自動（ゲームの言語）・日本語・English を切り替えられる。切り替えると、オプション画面の文字、ツールの案内、画面左上のボタンがその場で変わる。

日本語を表示するには、日本語フォントの入るMOD（日本語化MODなど）が必要。フォントが無いと文字化けする。

## ワークショップ用ファイル
- `Workshop/PreviewImage.png`（644×360）: ワークショップとコンテンツマネージャーに出るアイコン。ビルド時にModsフォルダへ一緒にコピーされる。元データは `Workshop/PreviewImage.svg`
- `Workshop/WorkshopDescription.txt`: ワークショップの説明文（日英、Steam BBCode、2,639字）

## 操作
| 操作 | 内容 |
|---|---|
| 画面左上 `Play` ボタン / `Ctrl+P` | ツールON/OFF |
| 左ドラッグ | 矩形で範囲指定 |
| 左クリック連打 | 多角形の頂点を追加 → 始点クリック or 右クリックで確定 |
| エリア上で `R` | 別の組み合わせ・別の入口位置で作り直す |
| エリア上で `Delete` | エリアと作ったもの（Prop・木・園路・柵）を削除 |
| `Esc` | 入力破棄 / ツール終了 |

ツール画面では境界線を緑、入口を黄色い円、園路を白線で表示する。

## 公園レイアウト（Layout = Park plan）
面積600m²以上のエリアに適用する。それより狭いエリアは従来のランダム配置になる。

1. **広場**: 範囲の中で一番広い所（境界から一番遠い点）を中心にする。中央にシェルター（東屋）を置き、周りに中心向きのベンチを並べる。周囲は周回路
2. **入口**: 外周を等分した位置に置く（既定は外周100mごとに1つ、2〜4か所）。ずらし方を何通りも試し、角から離れた辺の中ほどになる案を選ぶ。作り直すたびに候補の上位からランダムに選ぶ
3. **園路**: 各入口から広場の周回路へ。歩行者道ネットワーク（既定 `Pedestrian Pavement`）で作り、周回路とはノードを共有してつなぐ
4. **ゾーン**: 園路で区切られた区画（4つ未満なら広い区画を半分に割る）を、広い順に次の順で割り当てる。残りと狭すぎる区画は芝生

| ゾーン | 置くもの |
|---|---|
| アクティブ | 中心に大型複合遊具。周りに滑り台・ジャングルジム・回転遊具など。奥に日陰棚（パーゴラ/東屋）とベンチ。外周沿いにもベンチ |
| 幼児用 | 中心にブランコ。小さめの遊具（スプリング遊具・シーソー・小さい滑り台など）。園路側に見守り用ベンチ |
| 水遊び・砂場 | 水遊び遊具、砂場、中型の遊具。園路側にベンチ |
| 芝生 | 何も置かず広く空ける。園路沿いにベンチだけ |

5. **入口まわり**: トイレを置く。広い公園（3000m²超）では向かい合う2か所の入口に、入口を園路へ向けて置く。案内板は園路の反対側
6. **広場の近く**: ピクニックテーブル（面積に応じて1〜3台）と水飲み場を、芝生かアクティブのゾーン側に置く
7. **植樹**: 外周の3m内側に8m間隔で植える。入口・園路・Propの近くは避け、1公園につき1〜2種類
8. **柵**: 外周に張り、入口は空ける（ネットワーク優先、無ければProp）。空けるのは道路に食い込む所だけで、建物の敷地の中にも張る（設定で敷地も避けられる）

同じ公園の中では同じモデルを繰り返さないようにする。ベンチは公園全体で1種類に揃える。

## Propの判定（名前・タイトルのキーワード）
判定は次の順で行う: 案内板 → 除外 → トイレ → 水飲み → シェルター → 柵 → ピクニック → 遊具 → ベンチ → 汎用遊具

| 種類 | キーワード例 | 追加用の設定 |
|---|---|---|
| 案内板 | park sign, info board, notice board, 案内板 | `ExtraSignKeywords` |
| トイレ | toilet, restroom, lavatory, portaloo, トイレ, 便所 | `ExtraToiletKeywords` |
| 水飲み | drinking fountain, water fountain, bubbler, 水飲み | `ExtraDrinkKeywords` |
| シェルター/日陰棚 | shelter, gazebo, pavilion, pergola, arbor, canopy, 東屋, あずまや, パーゴラ, 藤棚 | `ExtraShelterKeywords` |
| 柵(Prop) | fence, railing, picket, hedge, 柵, フェンス, 生垣 | `ExtraFenceKeywords` |
| ピクニックテーブル | picnic, park table, テーブル | `ExtraPicnicKeywords` |
| 水遊び | splash, spray, water play, 水遊び, じゃぶじゃぶ | `ExtraWaterPlayKeywords` |
| 遊具 | swing, slide, seesaw, sandbox, merry, jungle, climb, spring rider, playground, play structure, 遊具 … | `ExtraKeywords` |
| ベンチ | bench, park seat, ベンチ | `ExtraBenchKeywords` |
| 柵(ネットワーク) | 柵と同じキーワード。高架/橋/トンネル/鉄道、車両レーンのあるものは除外 | `ExtraFenceNetKeywords` |
| 園路(ネットワーク) | 名前に pedestrian / footpath / park path を含み、歩行者レーンがあり車両レーンが無いもの | `PathNetName` で優先指定 |
| 木 | 高さ5〜40m。bush / shrub / hedge / flower / palm などは除外 | — |

- 大型複合遊具は「汎用遊具 or ジャングルジム系 or 滑り台」のうち、占有面積30m²以上のもの
- 見つかったものは `output_log.txt` に `[PlaygroundMod] found: …` と一覧で出る
- 設定ファイル: `%LOCALAPPDATA%\Colossal Order\Cities_Skylines\PlaygroundMod.xml`

## 住民の動き
- エリア周辺（既定320m）の住宅から、在宅中の住民を呼ぶ。子ども・10代が中心で、大人・高齢者も来る
- **家に一番近い入口から入り、園路を通って目的地へ行く**（目的地に一番近い園路上の点で園路を外れる）。帰りも同じ入口へ戻る
- **大人・高齢者**: 設定の確率でベンチ/シェルター/ピクニックテーブルへ行き、座って周りを眺める
- **子ども**: 遊具へ行く。満員なら休憩場所へ
- **用事**: 滞在中にトイレ（中に入って見えなくなる）か水飲み場（少し立ち止まる）へ行き、元の場所に戻る

| 遊具 | 動き |
|---|---|
| ブランコ | 横棒を支点にした振り子（最大約34°）。こぎ始めは小さく、だんだん大きく振り、降りる前にゆっくり止まる。振れに合わせて体を傾ける |
| シーソー | 2人そろった時だけ交互に上下（±0.4m、フレーム番号で同期）。板の傾きに合わせて体を傾ける。1人の時は自分の側を下げて待つ |
| 滑り台 | はしごの下へ歩く→登る→上で座る→だんだん速く滑り降りる→立ち上がってまたはしごへ、を繰り返す。どちらが上かはメッシュの高さで判定 |
| 回転遊具 | 座って周回する（同期） |
| 砂場 | 座って時々向きを変える |
| 複合遊具・ジャングルジム・水遊び | 周りを歩き回って立ち止まる |
| ベンチ・シェルター・ピクニックテーブル | 座って時々視線を動かす |

## 地形への追従
柵と園路のネットワークは、辺に沿って2mおきに地面の高さを調べる。直線（両端の地面の高さを結んだ線）とのズレが許容値（既定0.25m）を超えたら、一番ズレる所にノードを足して区切る。最短は4m、最長は48m。

平らな所ではノードを増やさない。ゲーム外で合成した地形で試したときの、直線とのズレの最大値は次のとおり。

| 地形 | 追従なし | 追従あり |
|---|---|---|
| 丘（高さ10m） | 1.14m | 0.36m（12セグメント） |
| でこぼこ（±2m） | 3.54m | 0.42m（17セグメント） |

- 柵Propは、1本ずつその位置の地面の高さに置く。Propは傾けられないので、急斜面では段差が出る。斜面ではネットワークの柵を推奨する

## 敷地の保護（建物を建てさせない）
| 仕組み | 内容 | 設定（既定） |
|---|---|---|
| 建設ブロック | `BuildingManager.CreateBuilding` にHarmonyのPrefixを当て、敷地（幅×奥行きのセル矩形）が公園にかかる成長型の建物（住宅・商業・工業・オフィス＝`PrivateBuildingAI` 系）は作らない。境界に接するだけの敷地は許す | Block houses/shops/offices/industry in parks（ON） |
| ゾーン消し | 公園の作成時とロード時、その後は約4秒ごとに、公園内にある区画のセルを「未指定」に戻す。塗り直しても戻るので、実質的にゾーン指定できない | Remove zoning inside parks（ON） |
| 手動配置の禁止 | 公共施設などを公園にかかる位置に置こうとすると、`BuildingTool.CheckSpace` に ObjectCollision エラーを足して赤表示にする。作成自体もブロックする | Also block placed buildings（OFF） |

- すでに建っている建物は壊さない（新しく建つのを防ぐだけ）
- 公園を削除すると制限も解除される。ゾーンは自動では戻らないので、塗り直せば建つようになる

## 設定（オプション画面）
- **Layout**: Layout（公園レイアウト/ランダム） / 遊具密度 / 園路をネットワークで作る / 園路幅 / 植樹 / 木の間隔
- **Visitors**: 最大人数 / 探す半径 / 大人も来る / 夜も来る / 大人が休憩場所を選ぶ確率 / トイレ確率 / 水飲み確率
- **Benches & Toilet**: ベンチ密度 / トイレを置く / トイレの最小面積 / ベンチ・トイレ等の向き反転
- **Park area protection**: 成長型の建物をブロック / 公園内のゾーンを消す / 手動配置の建物もブロック
- **Fence**: 柵を置く / ネットワーク優先 / 道路との重なりは空ける / 建物の敷地も空ける（既定OFF） / 地形に追従 / 追従の許容値 / 入口の数 / 入口の幅

## ゲーム本体のコードで確認済みのこと
実際の Assembly-CSharp.dll を読んで確認した。

- **座りポーズ**: `ResidentAI.SetRenderParameters` は、`AtTarget` と `SittingDown` が**両方**立っている時だけ座りモーションにする。このMODは座る時に両方を立てる（以前は `SittingDown` だけで、立ったままになっていた）
- **ベンチの座る位置**: ベンチなどのProp(`PropInfo.m_specialPlaces`)に設定された座る位置と向きを使う。変換式はバニラ(`BuildingAI.CalculateUnspawnPosition`)と同じ。`SittingDown` 付きの場所を優先し、アセットに設定が無ければ形から推定した位置に座る
- **立ち上がり**: バニラの `RequireSlowStart` と同様に、座っていた人が動き出す時は少し待ってから歩き出す
- **インスタンスが消されないか**: `HumanAI.SimulationStep` は `Character` フラグの無いインスタンスを到着扱いで解放する。このMODは `Spawn()` で `Character` を立てているので消されない
- **トイレで見えなくなるか**: 描画は `Frame.m_insideBuilding` が2フレーム続けて立ち、`HangAround` が無い時に省かれる。このMODはその状態にしている
- **ゾーンのセル位置の式**: `位置 + a*(列-3.5) + a2*(行-3.5)`（a = (cos,sin)*8、a2 = (a.y, -a.x)）は `ZoneBlock.CalculateBlock1` と一致
- **Propの回転**: 単体のPropも建物内のPropも `Quaternion.AngleAxis(角度, Vector3.down)` で描かれる（MOD全体の前提と一致）
- **シグネチャ**: `NetManager.CreateSegment`（10引数版と11引数版の両方がある）、`TreeManager.CreateTree`、`BuildingManager.CreateBuilding`、`ZoneBlock.SetZone / RefreshZoning` がMODの呼び方と一致
- **ビルド**: 実際のゲームDLL（Assembly-CSharp / ColossalManaged / ICities / UnityEngine）と Harmony 2.2.2 / CitiesHarmony.API 2.2.0 に対してコンパイルが通る

## 遊具の形の読み取り
滑り台・ブランコ・シーソーは、ロード時にメインスレッドでメッシュの頂点を読み、次のことを求める。
- 長辺方向の両端
- どちらの端が高いか（滑り台の上端）
- 高さ（ブランコの横棒）

読めないメッシュは、Propの大きさから推定する。読み取り結果は `output_log.txt` に `geom …` として出る。
ブランコとシーソーは、アセットに座る位置（`m_specialPlaces`）があればそれを座面にする。

座りモーションは、腰が「位置＋約0.42m」に来る前提（バニラのベンチと同じ置き方）。滑り台の滑り面の高さに合わせて、位置をその分下げている。

## 実機で見てほしいこと
1. ベンチ/トイレ/水飲み/案内板の前面を +Z と想定している。逆なら設定の Flip をON（座る位置と向きは、アセットに設定があればそちらを使うので影響しない）
2. 園路は公園の中で完結していて、外の道路にはつながない。バニラの住民が園路を経路に使うには、入口から歩道へつなぐ必要がある
3. 画像のような地面の色分け（ゴムチップ舗装・芝生の色）はバニラでは描けないので未対応
4. フェンスのネットワークを建物の敷地に重ねた時の挙動。問題があれば「Also leave gaps in building lots」をON
5. フェンスのネットワークに `m_flattenTerrain` があると、作成時に地面が削られることがある
6. セーブデータは v4。v1〜v3 のセーブもそのまま読める

## 開発時の検証
- ゲーム外で、ダミーのアセットを使ってレイアウトを生成し、画像に描いて確認（矩形・L字・小さい矩形）
- 敷地判定・地形追従の単体テスト
- 実際のゲームDLLに対するコンパイル
